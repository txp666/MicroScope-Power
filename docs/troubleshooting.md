# 排障说明

## Web 页面 404

确认 HTTP 服务根目录是 `web`：

```powershell
python -m http.server 8000 --bind 127.0.0.1 --directory web
```

浏览器打开：

```text
http://127.0.0.1:8000/
```

## 浏览器无法连接设备

检查：

- 使用 Chrome 或 Edge。
- 页面地址是 `http://127.0.0.1:8000/`。
- Pico 已烧录当前 UF2。
- Windows 设备管理器中能看到 USB 设备。
- 重新拔插 Pico 后刷新网页。

## 点击“固件升级”后没有出现 Pico 盘符

检查：

- 确认当前固件已经支持 `BOOTSEL` 命令。
- 点击前先停止采集，或直接让按钮流程自动停止采集。
- 等待 Windows 重新枚举 USB 设备。
- 如果没有盘符，手动按住 Pico `BOOTSEL` 重新插入 USB。
- 如果页面还是旧按钮状态，刷新 `http://127.0.0.1:8000/`，必要时强制刷新浏览器缓存。

## 上位机一直收到 0

优先检查硬件引脚：

| 信号 | Pico GPIO |
| --- | --- |
| MISO | GP16 |
| CS / CONVST | GP17 |
| SCLK | GP18 |
| DIN | GP19 |
| SEL | GP20 |

关键点：

- `CS / CONVST` 用于启动转换；当前固件转换时拉高，读数前拉低。
- `DIN` 固件保持高电平，使 ADS8866 进入 CS 模式。
- MISO 不要外接强上下拉。
- ADS8866 REF 必须有稳定 2.5V。
- 前端模拟地、Pico 地、被测负载地需要按硬件设计共地。

## 空载波形不为 0

空载输入可能悬空，ADS/放大器输出不一定回到零点。建议：

- 输入短接到定义好的零电流状态后归零。
- 两个量程分别归零。
- 使用固定电阻负载验证。

## 负载接入后波形乱跳

可能原因：

- 被测负载是低功耗间歇工作，电流本身在脉冲跳变。
- 自动量程在阈值附近切换。
- 小量程被大电流打满。
- 前端地线、Kelvin 采样或参考电压布局引入噪声。

排查顺序：

1. 先关闭自动量程，固定大量程。
2. 接固定电阻负载，确认波形稳定。
3. 再切小量程，看是否饱和。
4. 使用 100kSPS 验证通信稳定性。

## OLED 右侧花屏

当前驱动已增加 `OLED_CONTROLLER_X_OFFSET = 2`。如果换了不同 OLED 模块仍有边缘花屏，可调整：

```c
firmware/src/oled_ssd1306.c
#define OLED_CONTROLLER_X_OFFSET 2u
```

常见取值是 `0` 或 `2`。

## 设备卡死或无响应

重点怀疑：

- flash 保存期间异常。
- I2C 设备无响应导致重试。
- core1 高速采样状态未退出。

当前固件策略：

- USB 命令只标记保存请求，不直接写 flash。
- 采集运行时不写 flash。
- 空闲时才保存零点、电阻和 DAC 输出。

## DAC 输出不对

检查：

- I2C SDA/SCL 是否为 GP8/GP9。
- DAC60501 地址是否在 `0x48..0x4B`。
- LDO_EN 是否拉高。
- LDO_PG 是否为有效电平。
- ADC0 分压是否为 100k/100k。

OLED 显示的是 ADC 实测输出电压，不是 DAC 设定码。
